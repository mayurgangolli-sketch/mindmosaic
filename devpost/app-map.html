1. Application Purpose & Core Pieces

MindMosaic is a privacy-first emotional wellness journal and companion designed for students and working professionals. It balances immediate local data protection with compassionate, friend-first conversational AI support.

Welcome Screen (/)

Landing page introducing the app's calm philosophy, featuring Light/Dark/System theme toggling with zero flash-of-unstyled-theme.

Journal & Dialogue (/journal)

Active reflection composer with save-first local storage, privacy consent gates, conversational branching ("Talk more" vs "Get a suggestion"), and persistent memory controls.

Companion API (/api/chat)

Secure server-side proxy enforcing bounded requests, deterministic crisis/medical guards, system prompt guidelines, and swappable Groq/Mock AI providers.

History & Retrospective (/history)

Reverse-chronological session list, full retrospective dialogue review, individual session deletion, and clear-all controls with partition isolation.

3. The 3-Stop Code Tour Reference

Use these permanent anchors in the code to navigate the implementation:

  1. Stop 1: Frontend Submission & Consent Gate
    File: components/JournalEntry.tsx
    Key Function: handleSubmit(e) and dispatchAiTurn()
    Why it matters: Implements the save-first principle, writing to browser storage before evaluating sessionStorage.getItem('mindmosaic_consent_given') to gate external network calls.
  2. Stop 2: Server Safety Boundaries & Provider Adapter
    File: app/api/chat/route.ts
    Key Symbols: checkSafetyPatterns(), SYSTEM_PROMPT, and MockAIProvider
    Why it matters: Keeps API keys hidden on the server, intercepts medical/crisis signs deterministically before invoking AI, and transparently falls back to mock responses when offline.
  3. Stop 3: Partitioned Storage & Isolated Deletion
    File: lib/storage.ts
    Key Symbols: STORAGE_KEY, MEMORIES_KEY, deleteSession(), and saveSession()
    Why it matters: Separates raw reflections from approved memory observations. Deleting a reflection never erases approved memories, ensuring complete user autonomy.

5. A Practice to Reuse

Deterministic Safety Guards Before Statistical Models

The Decision: MindMosaic strictly evaluates deterministic regular expression guards (lib/safety.ts) before assembling prompts or dispatching to the AI model.

The Evidence: In scratch/test_slice4_branching.ts (Test 6) and scratch/test_chat_route_step2.ts (Tests 3 & 4), acute medical emergency signs and crisis expressions return verified emergency guidance immediately, bypassing conversational branching and LLM latency.

How to Reuse This: When building AI apps with high-stakes boundaries (health, compliance, legal, or finance), never delegate critical safety classification entirely to an LLM. Always place hard-coded, deterministic rules at the perimeter of your system.

Save-First Local Persistence

The Decision: Commit user input to local device memory synchronously before attempting any network or API dispatch.

How to Reuse This: For applications handling vulnerable user content (notes, drafts, forms), saving first protects user trust against flaky connectivity, mobile network dropouts, or backend timeouts.

6. How to Run MindMosaic Again

MindMosaic requires Node.js (v18+) and runs locally with zero external dependencies:

# 1. Install dependencies (if not already installed)
npm install

# 2. Start local development server
npm run dev

# 3. Open in your browser
http://localhost:3000

Note: To test with a live Groq model, copy .env.example to .env.local and add a free Groq API key. If omitted, MindMosaic transparently runs in offline simulated demo mode.
